# Паралельний пошук підрядка (KMP) на PARCS-Python

Лабораторна робота з курсу «Хмарні обчислення». Етап 1: послідовна реалізація,
генератор даних і перевірка логіки розбиття тексту на шматки (без PARCS і хмари).

Код сумісний з Python 2.7 і Python 3, використовує лише стандартну бібліотеку.

## Файли

| Файл | Що робить |
|---|---|
| `kmp.py` | `prefix_function`, `kmp_search` (позиції всіх входжень, включно з перекривними), `kmp_count` (лише кількість) |
| `chunking.py` | `split_with_overlap` ділить текст на шматки з перекриттям `m-1`; `parallel_search_simulated` послідовно імітує роботу воркерів |
| `data_generator.py` | генерує вхідний файл: перший рядок — зразок, другий — текст |
| `test_kmp.py` | тести (`unittest`): KMP проти наївного пошуку, крайові випадки, збіг паралельної імітації з послідовним пошуком, входження на межах шматків |
| `benchmark_sequential.py` | послідовний бенчмарк (базова лінія для звіту), дописує результат у `results/sequential.csv` |
| `solver_kmp.py` | розв'язок для PARCS-Python (єдиний файл, KMP і розбиття вбудовані); у вихідний файл пише кількість входжень і точні часи |
| `run_solver_local.py` | локальний запуск `solver_kmp.py` з імітованими воркерами — перевірка перед завантаженням у PARCS |
| `test_solver.py` | тести `solver_kmp.py`: копії функцій збігаються з `kmp.py`/`chunking.py`, результат збігається з послідовним пошуком |
| `DEPLOY.md` | покроковий план розгортання PARCS у Google Cloud і проведення замірів |

## Як розбивається текст

Текст довжини `n` ділиться на `k` «власних» частин `[start, own_end)` (розміри відрізняються
не більше ніж на 1). Воркер отримує `[start, end)`, де `end = min(own_end + m - 1, n)`,
і зараховує лише входження, що починаються у `[start, own_end)`. Перекриття `m-1` достатньо,
щоб дочитати входження, яке почалося в останній позиції власної частини, і замало, щоб
повністю вмістити входження, яке почалося вже в чужій частині, тож дублікатів немає.

## Запуск

Генерація даних:

```
python data_generator.py --size 1000000 --pattern GATTACA --insert 100 -o data/small.txt
python data_generator.py --size-mb 100 --pattern-length 12 --insert 1000 -o data/big_100mb.txt
```

Параметри: `--size` (символи) або `--size-mb`, `--alphabet` (за замовчуванням `ACGT`),
`--pattern` або `--pattern-length` (випадковий зразок), `--insert` (скільки копій
зразка гарантовано вставити), `--seed` (за замовчуванням 42), `-o` (вихідний файл).

Тести:

```
python -m unittest -v test_kmp test_solver
```

Локальна перевірка розв'язку для PARCS:

```
python run_solver_local.py data/small.txt --workers 4
```

Бенчмарк:

```
python benchmark_sequential.py data/small.txt
python benchmark_sequential.py data/big_100mb.txt --repeat 3
python benchmark_sequential.py data/small.txt --mode search   # з побудовою списку позицій
```

Згенеровані дані лежать у `data/` і не потрапляють у git (GitHub не приймає файли понад 100 МБ),
результати замірів зберігаються в `results/`.
